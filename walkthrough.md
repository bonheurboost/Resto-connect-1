# Security Summary

- **Strict Multi-Tenant Isolation**: Every tenant-owned record (menus, options, delivery zones, orders, cash sessions, payment transactions, inventory, employees, payroll, maintenance contracts, slug redirects, and visual branding) is partitioned by `restaurant_id`. In PostgreSQL migrations (`0001` through `0006`), Row-Level Security (RLS) restricts reads and writes to verified active members via `public.is_active_restaurant_member(restaurant_id)` (defined cleanly in `0006_prompt07_08_audit_commercial.sql`), and missing RLS write policies on `product_options`, `product_option_values`, `delivery_zones`, `order_item_options`, and `order_status_history` were added.
- **Controlled Signup & Role Escalation Prevention**: The `supabase/functions/controlled-signup/index.ts` Edge Function replaces any placeholder logic with strict invitation code validation against `public.restaurant_invitations`, verifies email matching and expiration, rejects any `super_admin` escalation attempts (`403`), creates the user with `platform_role: 'standard_user'`, inserts the `restaurant_members` assignment, rolls back on partial failure, and marks the invitation `'accepted'`.
- **Perpetual License Integrity**: Both `public.has_active_license` in PostgreSQL (`0006`) and `isLicenseOperational` in `src/lib/licensing/licenseRules.ts` enforce that perpetual licenses remain operational regardless of `maintenance_expires_at` or maintenance contract status, and can only be suspended or revoked by a Super Administrator.
- **Input, Media & Export Sanitization**: All public media URLs (`logo_url`, `cover_image_url`, `gallery_urls`) are validated through `sanitizeMediaUrl` (allowing only `http:`, `https:`, or bundled `/src/assets/` paths), hex colors through `validateHexColor`, slug changes against reserved platform routes and duplicates through `validateSlugChange`, and exported HTML receipts/commercial documents escape every interpolated string with `escapeHtml`.
- **No Client-Side Secrets**: Only `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are used in the browser; administrative operations requiring elevated privileges belong solely in Supabase Edge Functions (`SUPABASE_SERVICE_ROLE_KEY`).
